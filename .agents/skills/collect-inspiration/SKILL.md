# 收录灵感

每条灵感是一个**概念**：有名字、能拆解、能在别的网站上再次认出来。用户发来的网站只是**实例**（specimen）。一个概念挂多个实例，实例会改版或下线，概念不会。

## 步骤

### 1. 定层级和名字

先判断用户发来的东西属于哪一层，写进 `kind`。层级决定去哪里查名字：

| kind | 是什么 | 名字以哪里为准 |
|---|---|---|
| 组件 | 有固定状态和无障碍约定的界面零件，如 Tooltip、Hover card | WAI-ARIA APG、Open UI、component.gallery |
| 模式 | 几个零件组合起来解决一个界面问题，如钉住舞台、句子即界面 | NN/g、Tidwell《Designing Interfaces》、Mobbin 的分类 |
| 体裁 | 整页或整篇的组织方式，如滚动叙事 | 该体裁的源头文献，比如数据新闻领域的 Segel & Heer 2010 |
| 母题 | 不依赖实现的视觉典故、构图或隐喻，如创造亚当之手、外露网格 | 艺术史、平面设计史的通行叫法 |
| 技法 | 渲染或动效手段，如抖动、文字变形、粒子聚合 | MDN、W3C 规范、库的官方文档 |

用户一次发来的几个网站，常常是几个不同的概念，只是碰巧一起出现。比如“钉住的机位”“可见的网格”“材质填字”是三条，而不是一条“滚动效果”。按概念拆开，每次只收一条，其余的列给用户。

起名时先查现成叫法，查到就用，并记下出处链接。查不到再自己起名：模式写成“载体 + 动作”，母题写成“原型 + 母题”。规范里的机制名（如 `Scroll-driven animation`）指的是怎么实现，属于技法，所以放进 `uses`，不拿来做模式名。

查重：打开 `content/inspiration.json`，看 `name`、`aka`、`uses` 里是否已有这个概念。已有的话，就把新网站加进那条的 `similar`，不要新建条目。

完成标准：`kind` 已确定；名字要么是查到的现成叫法并附出处，要么按上面的公式起名；查重已做。

### 2. 在浏览器里核实每个链接

每个要写进去的网址，都在真浏览器里打开，并执行这个概念依赖的动作：滚动、悬停、点击、缩到 360px 宽度。只收录你**亲眼看到**这个效果的页面。作者名气、搜索摘要、HTML 里出现的 `sticky`/`step` 等词、其他 AI 转述的结论，都只是线索，不算证据。首页改版后效果消失的，要找到具体作品页，否则不收。

每个核实通过的链接写上 `captured`（核实日期）。重要的实例在 <https://web.archive.org/save/> 存一份，存档地址写进 `archive`。

完成标准：`source` 和每个 `similar` 都有当天的 `captured`；没有亲眼看到效果的链接已删除，并在汇报里列出删除原因。

### 3. 截图和录屏

```bash
node scripts/capture-inspiration.mjs <id> <url> [--video] [--scroll 0.4]
```

脚本按 1440×900 视口截首屏，缩到 800×500，存为 `public/inspiration/<id>.webp`。效果发生在滚动或时间里时加 `--video`：脚本会匀速滚动几秒并录下来，存为 `<id>.webm`；再手动在 `source` 里写 `"video": true`。动效只靠一张静态截图表达不了。脚本依赖全局安装的 Playwright、`cwebp` 和 `ffmpeg`，这些都装在 Mac 上。效果不在首屏的，用 `--scroll` 指定截图位置（0 到 1）。截图和录屏都要打开看一眼，确认拍到的是效果本身，而不是加载动画或 Cookie 弹窗。

无头浏览器被拦截（返回 403）或遇到 Cloudflare 人机验证时，用 `--headed` 改成有界面的真 Chrome；仍然不行，就换成带真人会话的浏览器手动截图。

### 4. 写条目

字段的机器规则由 `scripts/check-inspiration.mjs` 检查。下面写的是脚本查不出来的约定：

- `name`：中文主名，一眼能懂。`summary`：一句话说清是什么。
- `aka`：同一个概念的其他名字（同义词）。第一个是通行英文名，显示在卡片上。更底层的技法不放这里。
- `uses`：这个概念用到的更底层的组件或技法。写本站已有条目的 `id` 会自动变成站内链接；否则写英文通行名。
- `tags`：媒介，沿用已有的“视觉 / 排版 / 交互 / 动效”，确实需要时再加新的。
- `principle`：为什么成立。从它要解决的问题讲起，而不是从效果讲起。
- `parts` / `recipe`：拆成几个能独立复用的手段；再写一条最省事的实现路线。
- `avoid`：什么场景不该用，以及要付出的代价，包括可读性、可访问性、性能、移动端，最好附上出处。每一条都要写，写不出来，说明还没想清楚。
- `similar`：其他实例，`kind` 写变体。同一条里，变体按同一个维度取值，例如滚动叙事按“讲的是什么”分成数据、产品、尺度、创意。
- `kits`：能直接用的库、规范或教程，官方来源优先。
- `search`：以后找同类时用的英文搜索词。
- 对方允许 iframe 嵌入，并且实测不会跳出页面时，加 `"embed": true`。判断方法：响应头里没有 `X-Frame-Options`，`frame-ancestors` 也没有限制。

完成标准：`npm run content` 输出 `inspiration.json ok`。

### 5. 看页面并交付

运行 `npm run dev`，打开 `/inspiration/` 和 `/inspiration/<id>/`，按 1440 宽和 360 宽各看一遍：录屏能播放，链接能打开，`uses` 的站内链接能跳转。然后运行 `npm run build`。从 `main` 拉一个 `feat/inspiration-<id>` 分支，提交后开 PR。PR 页面里的 Cloudflare 预览链接要实际打开确认。
